# Behavioral Cycle Trader：实现、回测与审计

状态：2026-08-06 完成策略改造、DeepSeek 官方 API 全窗口回测、结果审计和 replay 审计。结论是：动态仓位和沙盒研究已经实现，但 10–40 日持有纪律仍不能仅靠提示词保证，当前版本不应被描述为已经达到预期。

## 1. 目标与边界

本 Agent 试图捕捉“低位供应收缩 → 试盘/假跌破 → 缩量回踩 → 确认拉升 → 派发或衰竭退出”的中段趋势。“建仓”“试盘”“洗盘”“派发”只是对可观察量价结构的可证伪假设，不是对操纵者真实意图的断言。

本实验只回答：在 TraderHarness 的点时数据、T+1、涨跌停、费用、撮合、日期遮蔽和实体遮蔽约束下，DeepSeek V4 Flash 能否一致执行这套交易合同。它不证明未来有效，也不构成投资建议。

研究依据包括：

- CMT Association 的 [Nine Classic Tests for Accumulation](https://cmtassociation.org/technically_speaking/technically-speaking-september-2015/)；
- Lo、Mamaysky 与 Wang 对技术形态自动化检验的 [NBER 工作论文](https://www.nber.org/papers/w7613)；
- Lee 与 Swaminathan 关于成交量与动量持续性的 [Journal of Finance 论文](https://onlinelibrary.wiley.com/doi/10.1111/0022-1082.00280)；
- Brock、Lakonishok 与 LeBaron 对移动均线和交易区间突破规则的 [Journal of Finance 论文](https://onlinelibrary.wiley.com/doi/abs/10.1111/j.1540-6261.1992.tb04681.x)。

这些资料只支持把量价模式机械化、做增量检验和基准比较，不支持“主力一定会拉升”之类不可验证的因果叙事。

## 2. 本轮实现

### 2.1 沙盒研究，而不是阶段打分工具

`traderharness/tools/analysis.py` 提供 `build_behavioral_cycle_features(ctx)`，在内存中生成点时安全的全市场特征表。表中只有原始可组合特征，不给阶段标签，也不提供综合分数。主要列包括：

- 60 日区间位置和 120 日回撤；
- 20 日涨跌、20 日 ATR、5/20 日 ATR 比；
- 5/20 日量比、涨跌日量比、CLV、OBV 流；
- 20 日突破幅度、支撑、阻力和更早阻力；
- 支撑触碰、近期突破、延伸和派发风险等布尔事实。

Agent 必须通过 `execute_code` 和 `traderharness_api.market.get_behavioral_features()` 自己组合、排序和检查参数敏感性。沙盒仍禁止直接读取 canonical dataset 或启动嵌套回测。

### 2.2 动态仓位

当前卡片位于 `traderharness/agents/builtin/behavioral-cycle.json`。实验不设低于现金账户自然边界的单股或总股票暴露硬上限；`max_position_pct=100` 只表达无杠杆现金账户的自然约束。关键锚点是：

- 每只新股票首次建仓通常为净值的 25%–40%；
- neutral 且一个确认机会时，目标总暴露 40%–70%；
- risk_on 且一个高质量机会时，目标总暴露 60%–80%；
- risk_on 且两个以上高质量机会时，目标总暴露 80%–100%；
- risk_off 或无确认机会时允许 0%–30%，宽度低于 35% 时禁止新增风险；
- 不得用低于 25% 的新票小仓机械填补暴露差额，不得向下摊平。

### 2.3 入场、持有和退出合同

- 低位和 test 只允许观察；入场必须来自至少一个已完整收盘交易日的确认。
- 首次突破日盘中不能追入；下一交易日仍守住突破位且未被放量长阴吞没时可以入场。
- 硬止损后冷却 10 个交易日，再入场必须重新确认并与全市场候选比较。
- 目标持有 10–40 个交易日；买入后前 5 个交易日只有结构止损、放量破位、重大事件或原始假设直接证伪才能退出。
- 每次交易理由必须包含市场状态、当前与目标暴露、阶段、证据、反证、仓位依据、结构止损、失效条件、加仓条件、退出计划和目标持有期。

### 2.4 基础设施修复

本轮同时修复了会污染仓位判断的基础问题：

- 常规 `get_portfolio` 缺少当前窗口价格时依次使用上一收盘价和成本价，不再把“现金”误报成“总资产”；
- 沙盒 Portfolio API 用最新可见价格计算持仓市值、浮盈和股票暴露；
- ToolAgent 累计收益以原始初始资金为分母，不再被日内上下文覆盖；
- 每个 CLI run 使用独立沙盒工作区；
- 沙盒模块导入在受控入口加载，仍由导入白名单阻止 `os` 等越权模块。

## 6. 符合预期的部分

1. 仓位不再过度保守。11 次首次建仓中 10 次按日终净值复算位于 25%–40%，600925 为 24.94%，属于价格/费用造成的 0.06 个百分点边界误差。
2. risk_on 时峰值股票暴露达到 94.89%，证明没有策略层面的 60% 总仓位天花板。
3. 没有向下摊平，没有重复下单尝试，没有下单错误，全部 24 笔交易理由的必填字段覆盖率为 100%。
4. 300024 是目标行为的正例：约 39.8% 首仓，持有约 22 个交易日，分两日退出，已实现盈利 37,660.27 元。
5. 工具调用从 2,372 降到 1,616；沙盒错误只有 5 次，所有越权导入均被正确拦截。
6. 95 个可验证日度组合快照全部满足 `total = cash + positions`，修复后没有“总资产只剩现金”的坏快照。

## 7. 未达到预期的部分

### 7.1 持有纪律失败

内置 behavior 指标给出平均持有 8.1 个日历日，但它对不同交易等权，容易被少数长单抬高。按实际卖出数量做 FIFO 复算后，平均只有 3.33 个交易日，中位数 1 日，79.62% 的卖出数量在 5 个交易日内完成，比原始保守版的 74.29% 更差。

部分提前退出确实触发了买入时的结构止损，例如 600080 在 2026-07-21 跌破原始 9.83/9.85 止损后卖出；但存在明确的事后改写：

- 000426 买入次日仍收在突破位之上，只因长上影主动减半；
- 300470 买入时止损为 3.59，次日最低 3.78，却把冲高回落重新解释为“派发”并清仓；
- 600020 买入时止损为 5.05，次日将止损临时上移至 5.50 后清仓；
- 600080 的交易理由声称已经持有 4 日，FIFO 交易日计数实际为 2 日。

这说明继续堆叠自然语言提示不会可靠解决问题。下一版需要把入场时的 `stage / structural_stop / invalidation / intended_holding_days` 保存为结构化 position plan；卖出时由环境显示原始计划、真实持有交易日，并对止损变更和 5 日内主观退出进行一致性校验。环境仍不替 Agent 计算阶段或择时，只负责防止它事后改写自己已提交的计划。

### 7.2 动态总仓位执行不一致

Agent 有时写下 risk_on 目标 60%–80%，但只建立 30%–40% 单仓，并自行发明“40% 上限”；这没有违反现金或硬上限，却与本实验的进攻锚点不一致。应把 `target_exposure` 和订单后暴露变成结构化字段，并由工具返回计划差额，而不是依赖自然语言自洽。

### 7.3 研究调用仍有浪费

最终版有 85 次 `get_behavioral_features()` 调用，分布在 29 个日期。同一复核日常在多段 `execute_code` 中重复读取相同特征表；第 80 日还把 “1, 6, 11...” 错算成复核日，随后第 81 日再次执行真正的计划复核。没有数据泄漏，但增加了 token 和工具成本。下一版应在同一交易日缓存一次特征快照，并把复核日判定放入只读 API 元数据。

## 9. 结论

这次改造解决了“仓位过小、专用工具替 Agent 打分、组合估值错误、调用过多”中的大部分工程问题，但没有解决最核心的交易行为问题：模型会在入场后用新的叙事覆盖原始计划，导致频繁的一日退出。最终版 -4.94% 也没有跑赢原始版 -4.45% 或 CSI 300 -2.97%。因此可交付结论不是“策略已经优化成功”，而是“动态进攻和沙盒研究路径验证成功，持仓计划必须结构化并由环境做一致性约束后才能进入下一轮正式 benchmark”。
